# G7.2 independent candidate and publisher preparation

## Candidate verification

`CandidateExecutionPins` is supplied by the operator, outside worker output: immutable workflow SHA-256, exact Python/scanner image digests, approved test module list. `prepare_candidate_inputs` accepts a complete trusted source snapshot and sealed result manifest, binds source/result/scope/expected head, reconstructs Git tree/commit objects and exports exact regular-file bytes into a new directory. For a future real candidate the trusted outer acquisition MUST first validate the G6.2 full result inspection and compare candidate parent/tree/every object/blob via the existing hash-checking reader against this deterministic candidate. This preparation API itself is not an independent PASS or permission to run/adopt anything.

The current read-only CI demonstrates synthetic `value.py` and `test_value.py` candidate objects only. Its workflow source commit (PR HEAD) is distinct from the synthetic Git candidate OID; no candidate branch or commit is published to GitHub. The synthetic candidate inventory, syntax, operator-owned behavior test, and full Gitleaks scan all use the exported entire candidate. Syntax/tests execute in a pinned Python container: nonroot 65534, root/source/candidate read-only, network none, cap-drop ALL, no-new-privileges, bounded pids/memory/CPU, tmpfs noexec/nosuid, no Docker socket, no token/key selector. Candidate self-tests do not determine PASS: an operator-owned trusted parent outside the candidate tree checks a separate interpreter’s exit and exact behavior. Candidate code cannot choose scanner config, ignore rules, trust pins, runner permissions, upload URL or final CI result. Proper scanner uses operator-owned default rules/no-ignore/redaction; positive clean fixture and intentionally synthetic secret negative are separate.

Host acquisition/metadata GET and attestation/upload remain outside candidate execution. The workflow emits its trusted run/attempt/job slug without tokens. A separately configured GET-only reader pins the actual numeric job ID and confirms that its job name, head, required steps and authentic artifact match. Existing workflow permissions remain exactly `contents: read`; no Actions permission is added. No repository Secrets/permissions change, write token or API billing route is introduced. The trusted workflow must itself be operator-pinned before any future real untrusted candidate can be used; a worker-controlled workflow must never be trusted.

`SyntheticCandidateQualificationReader` uses the existing strict CI contract/run/job/attempt/step and safe archive mechanisms. It authenticates actual archive bytes to GitHub digest metadata, pins workflow bytes, and checks every report binding with strict JSON/ZIP rules. Its G7.2 protocol and return type are audit-only, `QUALIFIED_SYNTHETIC_ONLY`, never production `VerificationEvidence`. The existing production G6.3 reader continues to require its original real-candidate protocol. Cross-run/job/attempt replay, wrong source/scope/head/candidate/workflow, forged status, unsafe ZIP, wrong digest and skipped/duplicated checks are rejected. Existing redirected archive/limits tests are retained and run.

A separately approved proof still needs acquisition of a real worker candidate and independently pinned production attestation at that candidate. Synthetic CI qualifies isolation/provenance machinery, not an actual worker result. Production failed-test attestation for corrective work is likewise not qualified by the fixture.

## Publisher preparation

`PublisherPreparationBoundary` wraps the existing exact-type G6.2 OFF preparer. It holds no credentials, HTTP write capability or runtime factory. Its proposal binds the inspected result, full source/scope/head, fixed repository/node/non-default ref, exact candidate, plan SHA-256, expiry and single `updateRefs` request: `beforeOid=expected_head`, `afterOid=candidate`, `force:false`. The proposal is deliberately a different protocol from a G6.3 approval and cannot be executed. Mutable mode/authorized flags cannot supply a missing capability.

Future capability acquisition is a required separate implementation/review AND explicit one-run human authorization, not an environment flag. It must bind a fresh known permission/rules envelope and subscription-only route, carry only the minimum operator credential outside model code, and reuse the G6.3 exact approval/expiry/one-update rules: create-only result/inspection/decision/intent, unique target lock, POST only plan-listed Git Database objects with exact SHA/object checks, read back every candidate tree/blob, fresh task/request/head/default/rules check immediately before call, durable `ref_intent`, exactly one GraphQL expected-head update, then GET/ref/object validation and immutable receipt. There is no such real capability in this batch. A ref fence or ambiguous network response forbids resend; restart may only GET, retain UNKNOWN, or finish the matching receipt. A historical receipt remains valid after later branch advancement and must not trigger a second update.

New adapter races cover default/head/task loss at fence, object tamper, lost reply before/after apply, death after fence/ref/checkpoint, competing sessions, late terminal and source cleanup. Existing G6.3 matrix also exercises expired approval, forged attestation, before/after fence, candidate mismatch, safe redirects/ZIP bounds and later-ref receipt replay. All sends are against injected credential-free fake GitHub.
