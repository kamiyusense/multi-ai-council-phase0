## Windows launcher (STATIC)
`codex-acp` starts `CODEX_PATH` through `cmd.exe` on Windows, so `codex_turn_gate.cmd` (LF file; `%~dp0` locates the gate, `RELAY_GATE_PYTHON` or `python` runs it, `exit /b %ERRORLEVEL%` propagates the code) is used. The gate now uses binary stdio (no CRLF translation) and runs a `.py` backend with the current interpreter. Tests (`tests/relay/test_codex_turn_gate.py`, Linux + Windows) cover argument pass-through, intact JSON-RPC, first generation allowed / second blocked, path with spaces, exit code, missing backend fail-closed, unparsable lines not forwarded. Windows workflow: `relay-codex-acp-windows-static-validation.yml` (carrier branch). Limits: the un-gated canary is Linux-only; the fixture backend is a Python script run by the gate (no exe packaging).
