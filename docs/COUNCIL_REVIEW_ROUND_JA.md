# Council の採点ラウンド（R2）と、手動の答えを混ぜた試験

- **決めた日**：2026-10-31（相棒の承認：先駆者調査の「おすすめ1〜4を全部入れる」＋「当面は手動の答えも混ぜて順位を付けさせる」）
- **理由**：AI 同士に答え直しをさせると多数派に同調して正解が消えることがある（先駆者調査：`/mnt/project-files/council/council-evolution-prior-art-20261101.md`）。前に同じ質問で手動と自動を比べたとき、上位がすべて手動だった。自動の精度が手動に追いつくまでは、手動の答えを混ぜて比べ続ける。

## 1. 何が変わったか

| | 前 | 今 |
|---|---|---|
| R1 の答え方 | 30行以内 | 結論→理由→リスク。長さの上限なし、根拠を付ける |
| 1人あたりの待ち時間（既定） | 5分 | 15分（`--timeout` で 30秒〜30分） |
| R2 | まとめを読んで答え直す | 匿名の答えを採点して、間違いを根拠つきで指摘する。書き直しはしない。最後の行に `順位: B > A > C` |
| Antigravity の R2 | 答え直し | 同じ採点のルール（`REVIEW_RULES`。2か所の文が同じかをテストで確かめる） |

## 2. 1つのお題の流れ（試験の間）

1. **R1（自動）**：いつもどおり。Grok・Claude・Codex・Antigravity が `r1_<AI名>.md` を置く。
2. **R1（手動）**：相棒が同じお題を、使いたいアプリ（例：ChatGPT・Claude・Gemini・Grok のアプリ）に手で聞く。答えをお題の担当 AI に渡すと、担当が掲示板に `r1_手動<アプリ名>.md` として置く。何個混ぜるかは相棒が決める。
3. **まとめ_r1.md**：担当が書く。前半はいつものまとめ（一致・不一致・UNKNOWN）。後半に、自動と手動の**答えの全文**を、A・B・C… の匿名で、順番をシャッフルして載せる。誰がどれかの対応表は、掲示板の外（例：`/mnt/project-files/council/<id>-key-r1.txt`、`A=Codex`・`B=手動ChatGPT` の形）に置く。
4. **R2（採点）**：担当が窓を開け、相棒が承認する。コマンドは R1 に `--round 2 --review` を足すだけ。
   ```
   python -m relay.council_run --review --round 2 --council-id <id>-r2 --question-file <00_お題.md> --quota-file <quota.json> --out <出力フォルダ> --board-dir <お題フォルダ>
   ```
   - Claude・Codex には、承認した時点のまとめ全文を質問と一緒に渡す。
   - Grok は質問を引数で渡す作りで長い文が入らないので、承認の後に `<出力フォルダ>/<id>/review/` にまとめだけを置き、そのフォルダだけを読ませる（書き込み・コマンドは禁止）。掲示板の名前付きのファイルは読ませない。
   - 承認の指紋には「採点ラウンド」と、まとめ全文の sha256 が入る。
   - 採点ラウンドではネット調査は**全員なし**（自動で切れる。`--web` を付けると呼び出し 0 回で止まる）。理由：まとめは外から来た文で、各 AI は PC のファイルを読めるので、ネットが開いているとファイルの中身を外へ送らされるおそれがある（💜 検品の指摘、2026-11-01）。
   - 1人の待ち時間は既定15分。3人なので、いちばん長くて約45分かかることがある。
   - Antigravity は、いつもどおり GO の札で `まとめ_r1.md` を読み、同じルールで採点する。R2 以降は設定にかかわらずネット調査なし。
5. **集計**：各 R2 の答えの最後の `順位:` の行を数え、答えごとの平均の順位と「自動の平均・手動の平均」を出す。決まった手順の計算だけで、多数決や AI の判定はしない。結果は答え合わせの記録として残し、相棒が「自動だけで足りるか」を決める材料にする。

## 3. 変わらないこと

- 各 AI に1回だけ聞く。再実行・自動の切り替え・API キーなし。GitHub には書かない。
- 承認の文字（A/B か、承認の文）は相棒が打つ。AI は打たない。
- 最終判断は相棒。順位は材料であって結論ではない。
- 手動の答えも掲示板の中では名前を伏せる（R2 の採点役が読むため）。
