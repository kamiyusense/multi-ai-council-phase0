# G7.2 lifecycle IO connection — STATIC only

The exact missing seam was identity plus durable ordering: G5's authentic `attempt_number` is `int(worker_run_id[:15],16)+1`, a random worker nonce. The campaign's `task.attempts` is a logical admission/budget counter. The G7.1 fixture used 1 for both and could not expose this production-format mismatch. G7.2 binds them in create-only lifetime AND unique logical-slot records. It never substitutes a large nonce into stored budgets.

`StaticObservationReceiptAdapter` is an injected call boundary, with no polling loop, scheduler, launcher, Issue close, model credentials or real publisher. Official Symphony continues to own tracker polling, task selection, workspace/worker lifetime, same-thread continuation, retry/backoff/stall and concurrency. The Official pinned patch is unchanged. The existing campaign kernel provides campaign advice/limits only; nothing here dispatches its advice into a second worker scheduler.

The G7.1 default identity check is unchanged for existing callers via one protected logical-counter method. G7.2 alone supplies its immutable binding. `_LineageView` copies one task for legacy G6 *checks* and delegates all mutations to the original kernel. Shared receipt/result collections remain canonical. No view is checkpointed; logical counters stay 1 in the authentic-nonce fixture. No G6 success policy was changed.

Order: externally selected admission → durable STARTED/binding → normal worker work/continuations → pre-close full snapshot/readback → authorized tracker close if appropriate → real Orchestrator lifecycle TERMINAL → independent qualification → mock receipt/checkpoint → next upstream decision. Snapshot `close_ready` means only that bytes survived; it does not authorize Issue close or claim task success. A CLOSED Issue requires existing independently authorized `symphony:adopt-after-close` scope permission; missing permission remains HOLD. G7.2 performs neither label mutation nor Issue close.

Recovery: missing TERMINAL stays HOLD without killing/relaunching; duplicate events/bindings are create-only; no snapshot exclusion hides unrelated files; post-snapshot changes cannot alter frozen bytes. Late unapproved workspace bytes inside the snapshot are not adopted. Lost receipt/ref reply uses original GET-only fence recovery, never resend; saved receipt plus missing campaign checkpoint can be applied/checkpointed without a second CAS. Concurrent checkpoint writers fail revision CAS. Unknown rules/task/head affect only the bound task.

Fixtures use authentic signed *formats* with a public fixture-only MAC and simulated GitHub/CI. They do not claim a real worker, model, independent real candidate attestation or actual Git adoption. Old generic World helper's unused manual legacy attempt is not counted as observed lifetime.
