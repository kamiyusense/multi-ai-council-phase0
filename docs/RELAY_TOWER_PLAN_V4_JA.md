## 1. 決まったこと

### 1-1. 正式な記録と掲示板
- 正式な記録はリポジトリ内のファイル（または専用ブランチ）に置く。Issue（#33 など）は掲示板で、正本ではない。
- 掲示板は Renovate の「Dependency Dashboard」と同じ形にする。Issue の本文は毎回作り直す。相棒が掲示板に付けたチェックや「承認」コメントは Control Tower が読み取り、正式な記録に反映する。

### 1-2. 誰が書くか
- 新しい鍵・PAT・GitHub App は作らない。
- AI（Claude、Grok Bot、Codex、Antigravity）は相棒の名義（kamiyusense）で書く。Grok Bot は Cursor の GitHub 連携を通して直接書く。Jules のコミットは `google-labs-jules[bot]` という別の名義になる。
- GitHub Actions（`github-actions[bot]` 名義）は、掲示板の作り直しと承認コメントの読み取りといった定期的な自動作業だけに使う。
- Actions が書いた変更では、別のワークフローは原則として起動しない（手動起動の `workflow_dispatch` と `repository_dispatch` は例外）。そのため、1回の実行の中で処理を最後まで終えるか、続きを `workflow_dispatch` で明示的に呼ぶ組み方にする。

### 1-3. 署名と承認
- **AI が GitHub に書くものには必ず署名を付ける。** 対象はコメント、Issue・PR の本文、コミットのメモ。
  - Claude：`Generated by Claude Code` / `Generated with [Claude Code]`
  - Grok：`AI-Agent: grok`
  - Codex：`AI-Agent: codex`（Symphony の Codex も含む）
  - Antigravity：`AI-Agent: antigravity`（Relay が作る貼り付け用の定型文の中で頼む）
  - Actions が AI の代わりに書くとき：依頼した AI の `AI-Agent: 名前`
- **AI は「承認」という語を単独で書かない。** 使うときは「承認待ち」「承認コメント」のように、必ず別の語とつなげる。
- **人間の承認として扱うのは、次の6つが全部そろったコメントだけ。**
  1. 書いたのが相棒（GitHub の ID 20355232）。
  2. 本文が「承認」の2文字だけ。前後の空白・改行と、最後の「。」は許す。
  3. どの署名も含まない。
  4. 書いたあと一度も編集されていない。
  5. 承認する対象（提案や PR）より後に書かれていて、対象の中身がそのとき（PR なら最新のコミット）から変わっていない。
  6. まだ使われていない。1回使ったら、使ったことを記録に残す。
  7. アプリ経由で書かれていない（`performed_via_github_app` が空）。S3 の試しで、Claude の書き込みは `claude`、Grok Bot は `cursor`、相棒のスマホは空と確認できたので追加した。
- 「承認します」「OK」などの言い方、相棒以外が書いたもの、Actions が書いたもの、署名付きのものは承認として扱わない。
- 署名は約束ごとで、GitHub が強制する仕組みではない。リポジトリ内で作る書き込み処理は、書く前に機械でチェックする（署名がなければ書かない、本文が「承認」だけなら書かない）。Grok Bot と Antigravity はこのチェックを通らずに書くので、指示文のルールだけが頼りになる。
- 無料プランの非公開リポジトリでは、ブランチ保護で承認を必須にすることはできない。守りはワークフローの中のチェックで行う。
- マージは今までどおり。AI がチャットで「マージしていい？」と聞き、相棒がチャットで答える。マージのメモには「approved by kamiyusense (chat approval)」と書く。これは「承認」コメントのルールとは別のもの。

### 1-5. Relay と Council
- Relay は相棒の PC で動かし、クラウドには置かない。
- Council（相談役）は Grok・Claude・Codex の3体。それぞれ公式の CLI（コマンドで動かす道具）を、サブスクのログインのまま使う。
  - Grok の起動は `grok --no-auto-update agent stdio` か `grok -p`。
  - API キー（`XAI_API_KEY` など）は、子プロセスに絶対に渡さない。
- Antigravity との流れ：
  1. 相棒が Relay に質問を書く。
  2. Relay が質問を3体に送り、相棒にも同じ質問を見せる。
  3. Relay が Antigravity 用の定型文（質問と回答の形式）を Markdown で作る。
  4. 相棒がその定型文を Antigravity に手で貼る。
  5. Antigravity の答えは、相棒が Relay に貼るか、Antigravity に GitHub の決まった場所へ書いてもらい、Relay がそこを読む。
  6. Relay が 4社の答えと相棒の意見をまとめて返す。
- 守る線：
  - 外部のツールから Antigravity を起動・操作・ラップしない（包んで動かさない）。
  - Antigravity が次の指示を読む場所へ自動で書かない。答えを書く場所と指示を読む場所は分けて、一方通行にする。
  - Antigravity の内部ファイル（`~/.gemini/` の会話履歴など）は読まない。読むのは成果物（PR・Issue・プロジェクト内のファイル）だけ。
- 例外（相棒、2026-10-25）：上の3つの線と、3章の「相棒が手で起動する」は、使い道を1つずつ決めて外せる。例：Antigravity 自身の Sidecars や `schedule` が Drive「AI掲示板」のお題フォルダを読み、`r1_Antigravity.md` を書く。外せるのは次のどちらかの時だけ。
  - (a) 相棒がその使い道をはっきり承認した時。
  - (b) Google の公式の規約や説明書が、はっきり認めている時。公式とは利用規約・FAQ・antigravity.google の説明書のこと。Google の社員と表示されていないフォーラムの回答は数えない。
  - 公式の書き方が UNKNOWN やあいまいな時は外さず、(a) で決める。外した使い道は、根拠と一緒に記録する。
  - 次は変えない：Relay・ACP・他社の CLI の中で `agy` を包んで動かさない。アカウントを切り替えて使わない。AI クレジットや超過課金を使わない（`useG1Credits` はオフ、AI Credit Overages は Never）。LIVE や初めての本番実行には、今までどおり相棒の承認の文が要る。
  - 使い道を外すまで、レーン `antigravity-manual` はそのまま。
- Antigravity の起動コードは削除しない。`archive/antigravity_launch/` に移して無効にし、冒頭に「使用停止中・実行禁止（規約上の理由、2026-10）」と書く。規約が変わったら戻せる形で残す。起動禁止リストは有効なまま。
- Grok の規約（相棒の調査）：
  - xAI 公式の告知（https://x.ai/news/grok-build-cli）に、ヘッドレス（画面なし、`-p`）でスクリプトや自動化に使えること、ACP で自作の bot やオーケストレーション（複数 AI のまとめ役）を作れることが書かれている。
  - 公式 docs（https://docs.x.ai/build/cli/headless-scripting）に、サブスクのログインで ACP から使う例がある。
  - 禁止されているのは、利用制限を回避することと、ログイン情報を他人と共有すること。
  - Claude や Codex と並べて自動・定期で動かすことについては、公式の記載がない（UNKNOWN）。
  - Grok CLI の利用枠は、Grok アプリ・Grok Bot と同じ週次の共有枠。

### 1-6. 指示役の代役
- 指示役は特定の AI ではなく「役割」として決める。必要な状態はすべて正式な記録に置き、どの AI が担当しても続きから再開できるようにする。
- 代役の候補と順番は設定ファイルで決める（例：Claude → Codex → Grok CLI）。Antigravity は候補に入れない。
- 同時に2体が指示役にならないように、担当者の記録（ロック）を置く。一定時間応答がなければ交代し、交代するときは引き継ぎメモを残して、相棒に日本語で報告する。
  - 部品は既存のもの（`loop_owner.py`・`claude_jules_handover.py`・`runtime_takeover.py`）を再利用する。
- 代役ができるのは、静的な作業（コード変更なし）と状態の報告だけ。1日の回数に上限を付ける。コード変更・マージ・本番設定の変更は、代役ではしない。

### 1-7. 利用枠
- 上限の数字は決め打ちしない。毎回、公式の方法で「残り何%か」を読む。
  - Claude Code：statusLine の `rate_limits`
  - Codex：app-server の rate limits
  - プランを上げれば、その瞬間から余裕が増えたと判断できる。
- 利用枠を読むために利用枠を使わない（AI に「残りいくつ？」と質問する方法は使わない）。
- 枠が読めないときは、その AI だけ休ませる。他の AI は動き続ける。掲示板に「枠が不明なので休止中」と表示し、相棒が「続けて OK」と言えば再開する。
- Grok はプログラムから残量を読む公式の方法がない（UNKNOWN）。週あたりの回数上限で管理し、上限は設定ファイルの数字1つで変えられるようにする。
- 追加クレジットは、ふだんは使わない。相棒が「今週はクレジットを使っていい」と承認したときだけ、その範囲で使う。自動購入は前提にしない。
- 稼働中の Claude×Jules ループ（prod-c1）の `on_quota_unknown`（枠が不明なときの扱い）を変えるときは、別に相棒の承認をもらう。

## 3. 残っているリスク
- 署名は約束ごと。AI が「署名を付け忘れる」と「承認と単独で書く」を同時にやった場合だけ、人間の承認と見分けられない。被害を小さくするため、1-3 の条件 4〜6（編集されていない・対象と結びついている・1回だけ）を入れている。
- 相棒の名義で書く AI が main に直接書くことは、技術的には止められない（今も同じ）。
- Claude を Council で呼ぶ場合、2026-11-12 から有効になる Anthropic の利用規約（AUP）では、「サブスク経由で他人のリクエストを流す」形が禁止される。Council は相棒本人の議題だけにし、回数も少なく保つ。
- 代役によって自動で動く回数が増える。Claude では、1日に 90〜300 回の自動実行でアカウントを停止された報告がある。代役には回数上限を付ける。
