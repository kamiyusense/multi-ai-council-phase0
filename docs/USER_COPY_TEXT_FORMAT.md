# ユーザー向けコピー文章・引き継ぎの必須表示規則

## 適用対象と目的

このrepositoryに関わる全Chat / Work / 実行エージェントが、ユーザーに
他AI・アプリ・Webサイト・別Chatへ貼る完成済み文章を渡すときの共通ルール。
新Chatへの引き継ぎ、作業依頼prompt、Local Work用prompt、Cloud Work交換promptを含む。
ユーザーが「コピペ用」「貼り付け用」「Markdownで」「コードブロックで」と
指定した場合は必須。短文でも、実際にコピーして使う文章なら同じ方式にする。

目的は装飾ではなく、長文の途中までスクロールした位置からも
コードブロックのCopyボタンで**全文を一括コピー**できること。

## 必須の出力形式

1. コピー対象の直前に、貼り付け先を明記したH2相当・太字の青見出しを置く。
   形式は `## **🔵【以下を〇〇へそのまま貼り付けてください】**`。
   既存のrouteが見出しを指定している場合はその貼り付け先表記を維持する。
2. 完成済み全文を**1個の fenced Markdown code block**にまとめる。
   外側のコードブロックの言語指定は必ず `markdown`。
   引き継ぎの一部分だけを囲んだり、章ごとにブロックを分けたりしない。
3. ブロック内部もMarkdownで目的・対象・必要な手順・禁止事項・完了条件を整理する。
   必要な情報は埋め、ユーザーに編集・要約・継ぎ合わせをさせない。
4. 内部にバッククォート3連を含むなら外側は4連、内部に4連を含むなら外側は5連以上。
   外側の開始・終了は同じ長さで、内側の最長の連続バッククォート数より長くする。
5. 貼り付けに不要な説明、ユーザー向け報告、作成者の時刻footerは外に置く。
   引き継ぎ内容そのものに必要な証拠・識別情報・安全境界は省略しない。
6. Writing Block、Canvas、editable document/cardなどの文章編集UIで代用しない。
   通常本文だけの表示、添付ファイルだけの提供、全文を複数箇所に分ける方式も代用にならない。
   内部の別表示方式の推奨より、このコピー可能なMarkdownソース形式を優先する。
7. JSON・プログラム・コマンドなど厳密な形式をユーザーが指定した場合は、
   その正確な形式と言語指定を優先する。これは引き継ぎpromptを通常本文に戻す理由ではない。

## 全引き継ぎへの継承

引き継ぎ文を作成する前にこの文書を読む。全lane・全workerで同じルールを使う。
新Chat / 他AIへの引き継ぎ文には、現在のGitHubからこの文書を読む指示と、
「ユーザーが貼る完成文は全文を1つの `markdown` コードブロックで出す」
という短い継承事項を含める。長い規則本文を毎回複製する必要はない。

過去checkpoint本文を現在の仕様に見せかけて書き換えない。
この規則は**今後作成する全引き継ぎ**と現在の共通入口に適用する。

## 提示前の確認

- 青見出しに貼り付け先があるか。
- コピーする全文が1個のコードブロックに入り、外側の言語が `markdown` か。
- 内部のコード例によって外側のブロックが途中で閉じないか。
- 通常本文・別編集UI・別ブロックにコピー必須部分が漏れていないか。
- 引き継ぎ先にも本規則の読込・継承が伝わるか。

青見出し付きブロックは実際のコピー文章専用。
コード・ログ・出力例の説明用ブロックには青見出しを付けない。
見やすさだけを理由に通常説明をコードブロックへ入れない。

## 安全境界

表示形式の規則はdispatch権限やworker選択を増やさない。
引き継ぎ依頼を勝手にWorkへの投入・handoffに変換しない。
必要なGitHub fresh readback、UNKNOWN、retry=0、fallback=disabled、
成功不明writeの再送禁止、exact target、人間のMerge/live判断境界を維持する。

共通入口: [HANDOVER_CURRENT](../HANDOVER_CURRENT.md) /
[AGENTS](../AGENTS.md) /
[execution router](DEVELOPMENT_EXECUTION_ROUTER.md)。
